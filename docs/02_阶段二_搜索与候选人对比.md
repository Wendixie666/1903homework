# 阶段 2：搜索、筛选与 Candidate 对比

## 目标

在阶段 1 已经能生成 Candidate Profile 的基础上，加入真正有使用价值的检索和对比能力。

核心闭环：

**多个候选人 → 标签筛选 / 自然语言筛选 → 找到 Candidate → 横向比较 → 查看各自证据**

本阶段重点不是继续增加更多候选人字段，而是让已有结构化数据真正“可搜索、可比较”。

---

## 3 人分工

### A：标签标准化 / AI 查询解析

负责：

- 对现有标签进行规范化
- 合并同义词
- 实现自然语言查询 → 结构化筛选条件

例如：

```text
"找有 LLM 和 software testing 经历的人"
```

转换为：

```json
{
  "research_interests": ["LLM", "software testing"]
}
```

还需要处理：

- LLM / large language model
- SE / software engineering
- CV / computer vision

等同义表达。

---

### B：搜索 / 筛选 / Compare API

负责：

- 多候选人数据读取
- 标签筛选
- 条件组合筛选
- Candidate Compare 数据接口
- 给自然语言查询提供结构化搜索入口

建议接口：

```text
GET  /api/candidates
POST /api/candidates/search
POST /api/candidates/nl-search
GET  /api/candidates/compare?ids=a,b
```

---

### C：搜索与对比 UI

负责：

- Candidate List
- Tag Filters
- Natural Language Search Box
- Candidate Compare 页面
- Candidate 快速切换
- 保持 Evidence 可追溯

页面不需要做得特别复杂，但搜索结果和比较关系必须清楚。

# 实施流程

## Step 1：先支持多个 Candidate

把阶段 1 的单候选人数据改为：

```text
candidates/
├── candidate_001.json
├── candidate_002.json
├── candidate_003.json
```

或等价的数据存储方式。

先准备 3–5 个测试 Candidate 即可。

---

## Step 2：实现标签规范化

避免同一个概念被写成多个标签：

```text
LLM
Large Language Model
large-language-model
大语言模型
```

最终统一为：

```text
LLM
```

建议维护简单映射：

```json
{
  "LLM": [
    "large language model",
    "large language models",
    "大语言模型"
  ]
}
```

第一版不需要构建复杂 ontology。

---

## Step 3：实现普通筛选

先实现确定性筛选：

```text
Research Area
Skills
Institution
Experience
Publication
```

例如：

```text
Research Area = LLM
AND
Skill = Software Testing
```

先确保标签筛选稳定，再做自然语言。

---

## Step 4：实现自然语言筛选

自然语言搜索框不是普通全文搜索。

输入：

```text
找做 LLM，同时有 software testing 经历，并且有开源项目的人
```

AI 只负责把用户意图转换成结构化条件：

```json
{
  "research_interests": ["LLM"],
  "skills": ["software testing"],
  "has_open_source_project": true
}
```

真正筛选仍然由后端执行。

这样可以：

- 降低 token 消耗
- 提高稳定性
- 避免 AI 每次重新阅读全部候选人

---

## Step 5：实现 Candidate Compare

第一版只比较已有事实，不做“谁更好”的自动结论。

建议比较：

```text
Candidate A         Candidate B

Research Area       Research Area
Education           Education
Experience          Experience
Publications        Publications
Awards              Awards
Skills              Skills
Evidence Status     Evidence Status
```

差异可以高亮，但不要偷偷修改原始数据。

---

## Step 6：保留 Evidence

搜索结果中的标签也应该能追溯：

例如点击：

```text
[Software Testing]
```

可以看到：

```text
来源：CV p.2
原始描述：...
```

Compare 页面同样保留证据入口。

  "skills": ["software testing"],
  "has_open_source_project": true

- 雷达图
- 自动 ranking

- [ ] 自然语言会被转换成结构化筛选条件

- [ ] 可以同时比较 2 个 Candidate
- [ ] Compare 页面可以查看来源
- [ ] 可以从搜索结果进入 Candidate Profile
- [ ] 可以快速切换 Candidate
